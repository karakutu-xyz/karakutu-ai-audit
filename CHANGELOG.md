# Changelog

## Unreleased

- Same-site boilerplate is now dropped from the removed article only when the candidate page also carries it. Before, a paragraph that two other live pages repeated (for example a background paragraph in follow-up stories) was dropped even when the candidate lacked it, so a copy missing that paragraph scored 100% and got `MOVED` with a false "100% contained" finding; it is now a partial fit and the audit goes on to web search. A copy on a different page template than the rest of the site (another footer or none) also no longer reaches `MOVED` at the similarity step. This changes verdicts; new runs get a new workflow ID.
- Auditing an imported archive article now loads its text from the archive when it is missing, as opening it does; before, the audit answered 422 `article_has_no_content` until the article had been opened once.
- The getting-started guide is now one ordered path from the demo to a real article audit: the model to load and how the containers reach it, the two settings real audits need (live ingestion and an API token), entering the token in the UI, archive import, the one-at-a-time queue, a run's result versus its details, search status, a second stack beside the main one, and troubleshooting.
- The API image now builds on Debian trixie instead of bookworm. Bookworm's older TLS handshake drew a Cloudflare bot challenge from some publishers, so their pages read as unreadable inside Docker while the same pages read fine natively; Docker runs now read them, which can change verdicts toward the native result. Similarity candidates that could not be read now record why (an HTTP status or a connection error class), and the run's step summary shows it.
- Record lean named step inputs referencing the run article, with catalog and archive/page evidence summaries by default. Exact model calls remain available beside step input in review; `RECORD_FULL_EVIDENCE=true` restores full private evidence for debugging. Computation, prompts and verdicts are unchanged; historical records remain readable.
- The checked-in OpenAPI contract is now `openapi.yaml` (sorted keys, block style, no anchors) instead of `openapi.json`, for easier reading and review; `scripts/export_openapi.py --check` still compares it byte for byte, and PyYAML is now a declared dev dependency. The running API still serves `/openapi.json`; no API behaviour changes.
- Return lean audit results with article identity, verdict and bounded evidence; keep full review data behind the explicit run details route and replace the portable record schema with version 2.
- Recognise dated same-publisher rewrites using measured headline and distinctive-word overlap: at least 35% of the original's headline words and 35% of its distinctive words, published at most two days apart. Short originals require near-identical headlines and at least 80% of the original headline words in the live text. Every rewrite must stay at the requested page or a same-article URL variant. Candidate headlines use the archive title, else the URL slug. In scope, web search must still match the story and compare key facts; a demoted rewrite is promoted only when no other same-publisher match qualifies under the existing relocation rule. Only the best rewrite is handed to web search; each prompt preserves its original budgeted pages and appends that rewrite if absent, including on smaller retries. At the low-interest exit a qualifying rewrite can give `LIKELY_MOVED` after the existing 50% partial-copy rule. Missing dates fail closed, unrelated siblings stay reviewer context, and findings and stage details show the numbers for human comparison. This changes verdicts; new runs get a new workflow ID.
- The bundled SearXNG now also queries mwmbl, a small independent web index. The default web engines often refuse this machine ("too many requests" or a CAPTCHA), which left live audits without web evidence; mwmbl answers. Big providers such as Yandex and Bing stay off because audit queries describe removed news. Web search can now find evidence it missed before, so verdicts can change; new runs get a new workflow ID.
- Count searches with no usable hits and unresponsive SearXNG engines as failed queries, and show degraded search status and the existing outage explanation.
- Same-publisher overlap is now scored after dropping same-site boilerplate (footers, subscription boxes, menus): paragraphs shared by two other live pages of the site that are clearly different articles, judged on text of their own that neither the removed article nor the other page has. The removed article never votes, copies of it cannot vote its body out, pages that redirect to another site do not vote, and when the learned boilerplate would cover more than half of the removed article nothing is dropped. An unrelated page that shares only a footer is set aside instead of being taken as the relocation, and a copy whose site furniture changed now measures as a move. With fewer than two other pages nothing is dropped. Known limit: two unrelated pages that quote the same passage of the article word for word can still weaken a partial copy (see the workflow guide). Review details keep raw and cleaned scores, the number of dropped paragraphs and the cap flag. The overlap bars were rechecked on cleaned invented pages and kept. This changes verdicts; new runs get a new workflow ID.
- A low-interest exit now keeps a measured same-publisher partial copy: holding at least 50% of the removed article's text gives `LIKELY_MOVED`; a smaller partial copy adds a relocation note to `LIKELY_LOW_PUBLIC_INTEREST`. Key facts are left for a person to compare. Verdicts can change, and new runs get a new workflow ID.
- Relevance now reads the article prose, not the first 2,000 characters of raw archive HTML, and its default prompt judges public affairs instead of wrongdoing only: laws, votes, budgets, public services, elections and rights are in scope without an allegation, and private matters of influential people (including private lawsuits) are out unless the story shows a public stake. This changes verdicts; an unedited relevance prompt moves to the new default on start, an edited one stays active. New runs get a new workflow ID.
- Two evidence fixes that can change verdicts. The source step now calls a cited page the same story, and hands it to web search as a lead, only when it holds at least 20% of the archived text (the existing sibling line); a readable cited page below that is reported as not shown to be the same story instead of "live". Related-removal key terms no longer treat all-caps header runs or labels as acronyms or company and legal-form pairs as names, and two-word names match only from a word start. New runs get a new workflow ID.
- Add a fabricated verdict benchmark set (15 invented Turkish cases, `--set verdict-quality`),
  `scripts/benchmark_compare.py` to line up two reports by workflow ID (fixed, broke, added and

- `make dev` stops every process it started on Ctrl-C, including one started an instant before the stop and not yet recorded, which used to keep running (most often seen as a flaky runner test on a busy machine). The runner test is now load-independent too: shell fakes instead of Python, event waits with a hang cap instead of 5-second budgets, its own process group, and an early runner exit fails at once with the runner's output.
- A step cut off by a stop now reads "Stage did not complete: the audit was stopped." (no outcome) instead of blaming the model, in new step records and in the audit story, including runs saved earlier; an unexpected error says so too. Real model failures keep their wording.
- `make dev` and `scripts/run-local.sh --check` now check offline that `web/node_modules` and the Python environment match `web/package-lock.json` and `uv.lock` before starting anything. A checkout pulled without reinstalling used to start Vite and fail in the browser on a missing import; now it stops with the command to run (`npm --prefix web ci` or `uv sync --frozen`). Nothing is printed when both are current, and nothing is installed or downloaded.
